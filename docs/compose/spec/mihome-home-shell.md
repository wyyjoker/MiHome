## [S1] Problem

当前 MiHome-Windows 主界面是「顶部家庭/房间 tab + 深色设备卡片网格」，信息密度低，缺少米家新版 App 的「家庭总览 → 房间聚焦 → 快捷控制」信息架构。用户无法在桌面端一眼看到：家里整体状态、需要关注的设备、各房间概览，以及选中房间后的侧栏快捷控制。

目标截图提供了明确视觉与信息架构参考：左侧全局导航、中部家庭首页信息流、右侧房间详情面板。本轮先落地**应用壳 + 家庭首页 + 房间面板**，旧能力保留可进入，未覆盖的侧栏页占位。

## [S2] Design

### 2.1 信息架构（本轮）

```
┌──────────┬────────────────────────────┬─────────────────┐
│ 左侧导航  │  主内容区（按导航切换）        │  右侧面板（可关）  │
│ 我的家    │  家庭首页（默认）             │  房间详情         │
│ 家庭*     │  房间列表                    │  快捷控制         │
│ 房间      │  设备（复用旧网格）            │  空调等气候卡      │
│ 设备*     │  场景/自动化/安防/能耗/消息=占位│                 │
│ 场景…     │  设置（复用旧设置）            │                 │
│ 设置      │                            │                 │
└──────────┴────────────────────────────┴─────────────────┘
```

- **默认路由**：启动进入「家庭」首页；登录流程不变。
- **设备**：侧栏点击后展示现有 `DeviceCard` 网格逻辑（可继续用旧的 room filter）。
- **设置 / 托盘 / 小爱 / 更新检测 / 单实例**：行为保持，入口从旧标题栏迁到侧栏与右上角。
- **右侧面板**：点选房间卡或房间列表项打开；可关闭；关闭后主内容占满。

### 2.2 视觉方向

风格锚点：米家新版 App / 小米 HyperOS 控制中心的浅色信息流卡片。

| Token | 值 | 说明 |
|-------|----|------|
| 背景 | `#F4F1EA` 系暖米色 | 主窗口底 |
| 卡片 | `#FFFFFF` / 微阴影 / 圆角 14–16 | 信息模块 |
| 主文字 | `#2B2A26` | 标题/主数值 |
| 次文字 | `#6E6A60` | 副标题/状态 |
| 主题色 | 沿用 `#3dbba4` | 开关 on、强调 |
| 强调暖 | `#C4A574` 可选 | 天气/装饰，克制使用 |

- 旧深色调色板保留，供旧网格/托盘在未迁移表面继续使用；新壳默认浅色米色。
- 主题切换：新壳至少支持「浅色米色」；深色米家壳若本轮未做完，设置里对新壳显示「暂用浅色」，不静默切回旧深色网格当首页。

### 2.3 家庭首页模块（自上而下）

1. **顶栏（内容区）**  
   标题「家庭」+ 右侧：刷新、设置入口。天气/空气质量若无 API 则不渲染。

2. **问候横幅**  
   - 文案：按时段生成「早上好 / 下午好 / 晚上好」+ 称呼。  
   - 称呼来源：设置项 `display_name`（新增，默认「你好」或截取米家昵称若可得）；无则「你好」。  
   - 副标题：汇总在线/离线、运行中设备数，例「家里目前一切正常」/「有 N 台设备离线」。  
   - 右侧装饰：渐变色块/抽象室内插画占位（本地资源，非外链）。

3. **状态摘要 chips**  
   从已知电源状态聚合（沿用现有轮询/探测结果）：  
   - 亮着的灯数量  
   - 运行中的空调数量  
   - 开启的窗帘数量  
   - 在线设备数  
   - 「当前模式」若无数据则省略；**在家人数 / 室外天气无可靠 API 时隐藏，不显示「--」噪音。**

4. **需要关注**  
   可折叠列表，来源：  
   - 离线设备  
   - 低电量（若 props 可读且低于阈值，默认 20%）  
   - 异常告警类 prop（若有）  
   空列表时整块隐藏。

5. **房间卡片网格**  
   - 数据：`DeviceInfo` 按 `room_name` 分组。  
   - 卡片：房间名、在线/离线计数、环境读数（已有 `_metrics` 则显示）、代表性设备 chips（灯/空调/窗帘优先）。  
   - 封面：本地生成的房间色相渐变占位（客厅暖黄、卧室蓝紫等映射），不下载实景图。  
   - 点击：打开右侧面板并选中该房间。

6. **常用设备**  
   - 数据：托盘配置 `tray.json` 中的设备，否则按模型类型取最多 6 台可快速开关的设备。  
   - 卡片：名称、房间、电源钮（复用探测逻辑）；点卡片打开现有详情工作台。

### 2.4 右侧房间面板

1. 头部：房间名、关闭钮、可选「更多」占位。  
2. 分类区块：灯光 / 气候 / 窗帘 / 影音 / 其他（按 model 关键字启发式，未识别归「其他」）。  
3. 每类一行摘要（N 盏灯 · M 开）+ 设备行；行内电源钮。  
4. **气候深控卡**（选中空调或房间内有空调时）：  
   - 温度 ±、模式（复用枚举 prop）、风速（若可写）  
   - 基于现有 `prop_widgets` / spec，不重写设备协议。  
5. 无空调/窗帘等设备时对应区块不出现。

### 2.5 导航与占位页

| 项 | 本轮行为 |
|----|----------|
| 家庭 | 完整首页 |
| 房间 | 纵向房间列表（与首页房间卡数据同源），点击开右栏 |
| 设备 | 旧设备网格迁入内容区（保留房间筛选） |
| 场景 / 自动化 / 安防 / 能耗 / 消息 | 统一占位：图标 + 「即将支持」 |
| 设置 | 打开现有 SettingsDialog（模态或内容区页均可，优先模态少改路径） |

### 2.6 布局与窗口

- 默认窗口建议最小 `980×640`，逻辑布局：侧栏 200–220px、主内容弹性、右栏 320–360px（可关）。  
- 无边框标题栏逻辑保留（拖拽/缩放/最大化）。  
- 继续走 `QT_SCALE_FACTOR` 缩放链路；新控件用逻辑像素 + 主题 token，避免写死物理 px。

### 2.7 数据与服务契约

- **不修改** `mijiaAPI` 调用面；继续唯一入口 `app/core/service.py`。  
- 首页聚合纯 UI 层：基于 `list_devices` + 现有批量属性轮询缓存。  
- 新增设置键（`settings_store`）：  
  - `display_name: str = "你好"`  
  - `home_shell_enabled: bool = true`（便于回退旧主窗结构；默认 true）  
- 禁止为「凑截图」伪造在家人数/天气/室内写实图。

### 2.8 错误与边界

- 未登录：沿用登录对话框，登录成功后再进首页。  
- 设备列表为空：空状态引导。  
- 轮询失败：chips 显示上次缓存并降级为次要样式，不弹栈。  
- 主题/语言：文案中文；不引入新 i18n 层。

## [S3] Out of Scope

- 自动化、安防、能耗、消息的真实业务与云端接口（场景手动执行已接入）
- 真实在家人数、室外天气、空气质量  
- 实景房间照片下载/自定义上传  
- 完整深色米家壳像素级还原  
- 移动端布局、多显示器高级特性  
- 改 mijiaAPI / 发新版本号 / 改构建脚本（除非入口文件名变化需同步 README 运行说明）
